# Saijou 实验源码中的统计机器学习原理

## 1. 这份 case learning 覆盖什么

本笔记以当前维护的 Saijou 实验链路为对象，而不是泛泛罗列深度学习术语：

```text
DNA 序列 + 四个 Saijou CPM bigWig 轨道
  -> AlphaGenome / Borzoi 的多任务监督微调
  -> 严格组成保持的 shuffle-ISM 扰动
  -> 鲁棒效应汇总、跨模型排序、阳性对照审计
```

主要源码入口：

- 微调：`src/ft-scripts/train_borzoi.py`、`src/ft-scripts/train_alphagenome.py`、`src/ft-scripts/borzoi_mmap_dataset.py`。
- 通用训练、损失与指标：`src/grelu/lightning/__init__.py`、`src/grelu/lightning/losses.py`、`src/grelu/lightning/metrics.py`。
- ISM 与结果验证：`src/grelu/interpret/ism/mutations.py`、`src/grelu/interpret/ism/runner.py`、`src/grelu/interpret/ism/validation.py`。
- Saijou 候选分析：`scripts/ism/experiments/saijou_hsc/analyze_saijou_all_genes_10bp_scan.py`、`scripts/ism/experiments/saijou_hsc/tools/effect_summary.py`、`scripts/ism/experiments/saijou_hsc/tools/region_importance.py`。

这里的“统计机器学习”包括：监督学习的目标函数、泛化评估、迁移学习、随机扰动实验、稳健统计、经验分位数校准和阳性对照评估。它不等同于“对每个碱基已经做了显著性检验”。

## 2. 总览：原则、源码实现与它回答的问题

| 层级 | 统计/机器学习原则 | 当前实现 | 它回答的问题 |
| --- | --- | --- | --- |
| 预测任务 | 多任务监督回归 | 同时预测 `hsc`、`mac`、`lsec`、`chol` 四条连续信号轨道 | 序列能否预测这四类细胞的覆盖度 profile？ |
| 目标建模 | 变换后的 MSE、Poisson、Poisson + multinomial | `target_mode` 可选；训练时按模式选择损失 | 是拟合平滑后的连续值、总 counts，还是 profile 形状加总量？ |
| 泛化 | 按染色体留出验证/测试集 | 训练、验证、测试分别使用不同整条染色体 | 在未见染色体上仍能预测吗，而不是只记住相邻窗口？ |
| 迁移学习 | 预训练主干 + 小范围参数更新 | head-only 或 LoRA | 小样本 Saijou 信号需要改变多少预训练表征？ |
| 优化稳定性 | Adam、梯度累积、梯度裁剪、早停 | 监控 `val_loss` 保存 top-k checkpoint | 如何在长序列、小 batch 下稳定优化并限制过拟合？ |
| 解释实验 | 组成保持的随机 shuffle 扰动 | 每个 10-bp edit 三个可复现 shuffle | 改掉该局部序列后，模型预测改变多少？ |
| 鲁棒汇总 | 中位数、MAD、滑动中位数 | 三个扰动重复的 median；局部 5 点 median | 结果是否被某一个随机替换或孤立尖峰主导？ |
| 可比性 | 参考信号分层后的经验分位数 | 对 `ref_sum` 的 `log1p` 分箱后排名 | 不同表达强度下的效应如何公平比较？ |
| 证据整合 | 跨模型 conjunction 与方向一致性 | `min(AG percentile, Borzoi percentile)` + sign agreement | 两个模型是否共同支持该候选，而非单模型偶然高分？ |
| 外部检验 | 注册阳性对照的 recall 与阈值敏感性 | 对多个阈值输出 recall | 选分数阈值时能召回多少已登记对照？ |
| 工程质量 | 完整性、唯一性、有限性、确定性检查 | 预期行数、主键重复、非有限值、重复推理差异 | 结果表是否足以被可信地分析？ |

## 3. 微调：从序列到四个连续 profile 的监督学习

### 3.1 多任务序列回归

当前训练将同一段 one-hot DNA 序列映射到四个 Saijou 轨道的 binned coverage profile。它是**多任务回归**：任务共享同一个预训练序列表征主干，但最后有四个输出任务。共享主干利用不同细胞轨道中的共同序列规律；多任务头则允许各轨道保留差异。

`train_borzoi.py` 在 155--162 行构造 `BorzoiPretrainedModel`，并将 `n_tasks` 设为 `len(TASK_NAMES)`；四个输入 bigWig 则在 133--139 行明确列出。AlphaGenome 脚本采用同一数据接口和同样的四任务语义。

这是预测模型的训练目标，不是差异表达的统计模型：每个 bin 是连续覆盖度目标，不是在拟合每个基因的组间 p 值。

### 3.2 目标变换与损失函数是在表达建模假设

原始 CPM coverage 非负、稀疏且长尾。`transform_binned_signal()` 先将 NaN 置零、负值截断为零，再按 32 bp（Borzoi 默认）或其他指定 bin 聚合。不同 `target_mode` 对应不同统计假设：

| 模式 | 标签构造 | 训练损失 | 隐含偏好 |
| --- | --- | --- | --- |
| `log1p_mse` | 每 bin 平均 coverage 后取 `log(1+x)` | MSE | 压缩极端峰，较重视低/中信号的相对误差 |
| `borzoi_squash_mse` | sum 后做 Borzoi 风格非线性 squash | MSE | 保留 count 方向但降低大峰支配性 |
| `poisson` | 每 bin raw count sum | Poisson NLL | 将非负 count 当作 Poisson 型随机变量 |
| `poisson_multinomial` | 每 bin raw count sum | multinomial shape + 加权 Poisson total | 同时拟合 profile 内的空间分布与总 counts |

对应实现见 `borzoi_mmap_dataset.py::transform_binned_signal` 以及 `train_borzoi.py` 164--174 行。`PoissonMultinomialLoss` 将预测总量的 Poisson negative log-likelihood 与归一化 profile 的 multinomial 项相加；`total_weight` 控制前者权重（`losses.py` 70--91 行）。因此“选什么 loss”不是纯工程参数，而是对模型应优先学习**绝对强度**还是**空间形状**的选择。

### 3.3 按染色体切分：针对基因组邻近泄漏的泛化设计

`make_borzoi_splits_mouse.py` 将验证和测试分别留给整条染色体，例如 `split_chr10_chr11` 使用 chr10 验证、chr11 测试，其余常染色体训练。窗口在单条染色体上按固定 stride 生成；该设计避免随机打散相邻窗口后，几乎相同的序列上下文同时进入 train 与 validation。

这是一种**group holdout / domain holdout**：估计的是“面对未见染色体的泛化”。它通常比随机窗口切分更严格，但并不自动保证跨实验、跨测序批次或跨生物样本的泛化。还要注意：当前 `build_dataset_pair()` 只向训练器交付 train 与 val；生成的 test split 必须在独立的事后评估中真正使用，才构成最终无偏测试。

### 3.4 数据增强与标签同变换

训练集设置 `rc=True, augment_mode="random"`，验证集关闭 reverse-complement 增强（`borzoi_mmap_dataset.py::build_dataset_pair`）。这是利用 DNA 双链对称性的**标签保持数据增强**：序列翻转互补时，profile 标签也由 dataset 的 augmenter 同步变换。验证不增强，使验证损失代表固定输入分布。

这里的随机性用于扩增训练样本，并非生物学重复，也不能直接当作不确定性区间。

## 4. 迁移学习与优化：限制可学习自由度，保护预训练知识

### 4.1 head-only 与 LoRA

- **head-only**：冻结预训练 embedding，仅训练新的四轨输出头（`train_borzoi.py` 87--89、217--219 行）。这是低自由度基线：若它表现已足够好，说明预训练表征可直接迁移。
- **LoRA**：不更新原始大矩阵，而在选定的 `Conv1d` / `Linear` 模块上学习低秩增量。对线性层可抽象为 `W' = W + BA`，其中 `rank=r` 明显小于原矩阵秩；`alpha/r` 决定增量尺度。代码以 `r=8`、`alpha=16` 为默认值，并只匹配 Borzoi 的部分卷积、注意力 `q/v` 和 FFN 层（101--128 行）。

这两种策略都是**参数高效迁移学习**。它们降低小数据全参微调的过拟合和灾难性遗忘风险，但同时限制可表达的领域适配幅度。二者应在完全相同的 split、目标变换和验证指标下比较。

### 4.2 优化稳定性不是泛化证据

默认训练使用 Adam；小 batch 通过 `accumulate_grad_batches` 形成较大的有效 batch，并使用梯度裁剪（默认范数阈值 1.0）限制偶发的大梯度。checkpoint 和 early stopping 都监控最小的 `val_loss`，耐心值为 3（`train_borzoi.py` 176--208 行）。冻结模式还固定主干的训练/归一化状态，防止“参数没训练但 BatchNorm 统计量漂移”。

这些做法提高优化稳定性，但不能替代独立 test、重复训练 seed 或生物学外部验证；最低 `val_loss` 只是当前验证集上的模型选择准则。

## 5. 评估：误差、相关性与数值稳定性

`grelu.lightning` 对回归任务同时维护 MSE、Pearson、以及二者的 `log1p` 版本。它们分别反映不同性质：

- **MSE**：绝对预测偏差，峰值很大时容易被少数高覆盖 bin 主导。
- **Pearson r**：预测与观测的线性协变程度；即使整体尺度偏差较大，只要形状同向仍可较高。常数预测或常数目标时 r 未定义，源码返回 NaN。
- **log1p-MSE / log1p-Pearson**：在将非负 coverage 压缩后计算，减弱长尾峰对指标的垄断。代码特意使用 float64 累积 Pearson 的充分统计量 `sum_x, sum_y, sum_xx, sum_yy, sum_xy`，再在全验证集计算 covariance / variance，以降低稀疏大动态范围信号的数值误差。

因此不应只报告一种指标，也不要把“Pearson 高”直接解读为“绝对 CPM 校准良好”。训练的 `val_loss`、raw/log scale MSE、raw/log scale Pearson 和正对照 profile 图各自回答不同问题。

## 6. ISM：受控扰动实验，而不是训练集上的特征重要性捷径

### 6.1 严格 shuffle 设计

Saijou ISM 在 TSS 锚定扫描中把每个 10-bp 原序列替换为三个**组成保持且彼此不同**的 shuffle。替换的随机数由 `SHA-256(seed, mutation_key)` 派生，因此同一 manifest 可完全复现（`mutations.py` 92--154、244--284 行）。

保持碱基组成的意义是：在比较原序列与替换序列时，尽量控制局部 GC/单核苷酸 composition；剩下的变化更接近于局部顺序/基序语法被破坏的效应。它比任意随机替换更适合作为局部背景，但仍不是完美的因果干预：10 bp 窗口可能同时破坏多个 motif，也会改变更高阶序列结构。

### 6.2 效应量、重复与鲁棒摘要

核心效应字段是预测 profile 汇总后的 `log2fc_ratio_of_sums`。每个中心、每个 readout、每个 track 有三个 shuffle 重复：

- 以 **median signed log2FC** 保留效应方向；
- 以 **median absolute log2FC** 衡量强度；
- 以标准差或 **MAD** 描述三个替换的离散程度；
- 对绘图曲线使用 5 点中心滑动中位数，抑制孤立尖峰。

`effect_summary.py` 29--99 行特别声明：该摘要是 effect size，不是 significance estimate。三个 deterministic shuffles 是对替换背景敏感性的有限技术重复，不能被误称为独立生物学重复，也没有在这里构造 p 值、置信区间或 FDR。

### 6.3 数据完整性本身也是统计前提

ISM runner 在合并结果时检查：实际 feature 行数是否等于 `mutation × readout × track` 的期望行数、核心数值是否有限、复合主键是否重复，并检查重复推理的最大差异（`runner.py`、`validation.py`）。候选分析还要求每个保留中心恰有 3 个替换重复。

这不是“模型表现指标”，但它是后续 median、percentile 和对照 recall 有定义的前提；不完整或重复表会制造假高分或改变经验分布。

## 7. 从 ISM 效应到候选区域：排名规则的统计含义

### 7.1 先按参考表达强度校准，再计算尾部分位数

`region_importance.py::summarize_model` 对每个模型、细胞轨道和固定 readout：

1. 计算三个 shuffle 的 median absolute / signed log2FC 及 MAD；
2. 对 `median_ref_sum` 做 `log1p` 后按近等频分箱；
3. 在每个参考信号分层内，对 absolute effect 求经验 percentile。

这是一种**分层的经验分布校准**。其动机是：低表达与高表达 readout 的可达到效应幅度不同，直接比较 raw absolute log2FC 容易让一种信号尺度主导。它给出的 95 分不是“零假设下 5% 的 p 值”，而是“在同模型、同轨道、同 readout、相近参考强度的扫描位置中位于经验尾部”。

### 7.2 跨模型 conjunction 是保守的共识规则

同一个 `(gene, offset, track, readout)` 的 AlphaGenome 与 Borzoi percentile 合并为：

`cross_model_conjunction = min(percentile_AG, percentile_Borzoi)`

并记录两个 median signed effect 是否同号。取最小值相当于“短板原则”：只有两个模型都认为异常靠前时，候选才高分。随后在同一中心的四个细胞轨道/readout 机会中选择最佳条目，再把 conjunction 的全局 percentile 映射为 0--100 的 `importance_score`。

它降低单模型偶然峰被突出展示的风险，却仍是**候选发现排序**，不是两个独立统计检验的正式合并，也没有从模型相关性推导显著性。

### 7.3 区域调用、平滑和选择偏差

超过阈值的非 splice-overlapping centers 按相邻间距聚类；每段取 top-3 center score 平均为 `region_score`，并限制每基因最多若干段。这样将单点信号变为局部一致的区域证据。

但请保留三个边界：

1. 5 点滑动 median 是可视化/稳健描述，不应被作为独立证据重复计数；
2. “取四个轨道/readout 中最佳”属于多重机会选择，会使候选排名偏乐观；
3. 本项目用固定 readout、跨模型最小分位数、方向一致性和阳性对照来缓解，而非宣称已完成全基因组 FDR 控制。

## 8. 阳性对照：阈值的外部、但有限的校准

代码读取预注册的 TF--gene 区间，对每个对照找覆盖的 ISM centers，并记录最佳分数、是否在阈值处被召回；同时输出 50、60、70、80、90、95、97.5 等阈值下的 recall 曲线。

这相当于把候选打分视为一个排序器，用已知对照估计其**检出灵敏度（recall）**。它很有价值，因为阈值不只由当前数据分布决定；但它不是完整的分类性能评估：

- 对照集很小且不代表所有真实调控元件；
- 未召回的对照可能是模型、坐标、readout 或扫描分辨率不匹配，不必然是“假阴性”；
- 没有经过同样审计的负对照集时，不能由 recall 单独得到 precision、FPR 或 ROC-AUC。

## 9. 当前源码明确没有做什么

以下区分对解释结论很重要：

| 不应声称已经完成 | 当前实际情况 |
| --- | --- |
| 每个 10-bp 区域有 p 值 / q 值 | 当前为 deterministic shuffle 的效应量、离散度和经验分位数排序；没有零分布检验和多重校正。 |
| 三个 shuffle 等于三个生物学重复 | 它们是同一 reference 窗口的三个序列背景替换。 |
| `importance_score=95` 等于 95% 后验概率或 0.05 显著性 | 它是经过分层和跨模型合取后，再经验排序得到的分数。 |
| validation 最优 checkpoint 已证明最终泛化 | 当前模型选择使用 val；test split 需独立、一次性地评估。 |
| 高 Pearson 已证明定量预测准确 | Pearson 主要衡量线性同变；需结合 MSE、loss、尺度和 profile 图。 |
| motif 命中即证明真实 TF 因果机制 | ISM 证明的是模型对该序列扰动敏感；motif 注释是机制假设，需要外部实验或独立数据支撑。 |

## 10. 阅读源码的推荐顺序

1. 先看 `experiments/RUNBOOK.md` 和 `src/ft-scripts/train_borzoi.py`，建立数据、任务、loss、LoRA/head-only 和 checkpoint 的全局图。
2. 再看 `borzoi_mmap_dataset.py` 与 `make_borzoi_splits_mouse.py`，确认标签变换、增强和染色体 holdout。
3. 看 `losses.py`、`metrics.py`，理解训练目标与报告指标并非同一件事。
4. 看 `src/grelu/interpret/ism/mutations.py`、`validation.py`，理解“扰动”如何可复现且如何进行表级质量控制。
5. 最后看 `region_importance.py` 和 `effect_summary.py`，把 raw log2FC 如何变成“候选区域”的经验排序规则逐项拆开。

如果后续希望把“候选排名”升级为更正式的统计推断，首先应先定义独立的零假设、可交换的背景生成机制、单位（窗口、基因还是区域）和多重比较族；这些目前都不是现有 score 的隐含含义。
